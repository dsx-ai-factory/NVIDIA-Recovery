# NVIDIA Recovery v1.0.0-beta.1

This beta release is intended for QA evaluation. NVIDIA Recovery remains
experimental and is not ready for production use.

## Highlights

- Recover Slurm and Slinky workloads through the scheduler-neutral Advisor API,
  including attempt-aware DAG recovery, watchdog release safeguards, and
  checkpoint-based restart flows.
- Record recovery audit events across detection, advice, scheduler action, and
  job lifecycle stages, with timeline and filtering support in the dashboard.
- Support provider-native Loki and VictoriaLogs query backends. Optional NVIDIA
  Attribution remains disabled by default and requires separate access and
  qualification.
- Improve Slurm controller throughput and observability with bounded concurrent
  reconciliation, asynchronous log metadata enrichment, shared OTLP export, and
  stage/source latency metrics.
- Publish public documentation, source packaging, and the `nvidia-recovery` umbrella
  Helm chart without private Attribution source or credentials.

## Compatibility and upgrade notes

- This beta may change APIs, configuration, and behavior before a stable 1.0
  release. Review the Gateway HTTP/gRPC, Adapter, Advice, and Helm configuration
  documentation before upgrading.
- The legacy Job Manager recovery-request and relay queues are removed. Recovery
  state and actions use the Advisor and Advice contracts; deployments must not
  depend on the retired queue paths.
- Advice Operator is not part of the supported release. Slurm and Slinky
  integrations use the Slurm Advisor Controller.
- Operators build service images from this exact source revision, publish them
  to their own registry, and configure the chart with those image references.
  NVIDIA Recovery does not publish product container images in this release.

## Qualification boundaries

- The tagged workflow validates reproducible source and Helm archives, checks
  their contents, and runs Helm lint/render. Those checks do not exercise a live
  scheduler, GPU cluster, provider, image build, installation, or recovery
  scenario.
- Public CI and the tagged public E2E suite must pass for the exact release
  commit before publication. Private Attribution qualification is separate and
  is not a public release prerequisite.
- Dependency vulnerability and license review remains part of maintainer release
  approval. The chart retains third-party license and notice material, including
  the bundled MinIO chart's AGPLv3 material.
- Secret scanning/removal and release signing/provenance are not established by
  archive checksums. SHA-256 checksums detect byte changes but do not identify a
  signer.
