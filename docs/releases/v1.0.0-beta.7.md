# NVIDIA Recovery v1.0.0-beta.7

This beta release is intended for QA evaluation. NVIDIA Recovery remains
experimental and is not ready for production use.

## Highlights

- Generate dashboard session secrets per release, reuse stored keys on upgrades,
  and support explicitly supplied keys or an operator-managed Secret.
- Fix credential-free Fern documentation validation and local rendering under
  the configured hosting path.
- Run tagged E2E independently of source and Helm release publication while
  retaining result reporting.

## Compatibility and upgrade notes

- Upgrading from the dashboard's former fixed session keys requires supplying
  two new keys or selecting an operator-managed Secret. Rotating these keys
  invalidates existing sessions and requires users to sign in again.
- Enabling the dashboard for the first time in an existing umbrella release
  also requires supplied keys or an existing Secret. GitOps deployments should
  supply stable keys or reference an operator-managed Secret.
- Operators build service images from this source revision and configure the
  chart with their own registry references. This release does not publish
  product container images.
- This beta may change APIs, configuration, and behavior before a stable 1.0
  release. See the [Helm guide](../../deploy/helm/README.md) for session-key
  migration and offline-rendering details.

## Qualification boundaries

- Publication requires successful public code and documentation CI for the exact
  release commit, protected release tags, archive checks, and environment approval.
  Tagged E2E reports independently and does not block publication.
- Packaging validates reproducible source and Helm archives and runs Helm
  lint/render. These checks do not establish live scheduler, GPU, installation,
  authenticated session migration, or recovery qualification.
- Private Attribution qualification is separate and is not a public release
  prerequisite. Dependency vulnerability and license review remains part of
  maintainer release approval.
- Archive checksums detect byte changes; they do not establish signing,
  provenance, or secret scanning.
